# ParentPilot

A mobile-first web app that coaches a **parent** through helping their child
with homework. Photograph a worksheet, including whatever the child has
already written, and get back a plain-language primer on what is being taught,
a side-by-side comparison of the method you learned against the method the
curriculum expects, and five questions to ask in order. The answer sits behind
a press-and-hold lock. Live Mode listens to the session and surfaces coaching
when the parent gives away the answer, uses generic praise, or transmits math
anxiety.

**The constraint that defines this product: the AI speaks only to the adult.
The child never touches the device and is never addressed by the model.**
There is no child-facing chat, no student login, and no kid mode. That rule
is enforced in three places, not one: every prompt file carries it as a
standing rule, the schema has no child account to authenticate as, and
`/check` returns a response shape with nowhere to put an answer.

---

## Running it

```bash
npm install
cp .env.example .env        # fill in the values below
npm run db:migrate          # creates the schema and the pgvector column
npm run seed                # imports 70 standards and 20 misconceptions, embeds them
npm run dev
```

```bash
npm run check               # 91 deterministic checks, no network, no key needed
npm run typecheck           # tsc --noEmit, strict
npm run build               # production build
```

### Environment

| Variable | Purpose |
|---|---|
| `OPENAI_API_KEY` | Model calls. Without it the app serves the cached demo packet everywhere, with an honest banner, rather than erroring. |
| `DATABASE_URL` | Postgres with the `pgvector` extension (Neon or Supabase). |
| `NEXT_PUBLIC_APP_URL` | Absolute URL, used for OG tags. |
| `OPS_PASSWORD` | Single password gating `/ops`. Unset closes the page. |
| `DAILY_SPEND_CEILING_USD` | Defaults to 15. |

Model IDs are overridable per task (`OPENAI_VISION_MODEL`, `OPENAI_PACKET_MODEL`,
`OPENAI_CLASSIFY_MODEL`, `OPENAI_RECAP_MODEL`, `OPENAI_EMBEDDING_MODEL`) so a
model can be rolled without a code change. The routing table and its defaults
live in `lib/ai/provider.ts` and are displayed on `/ops`.

### Deploying

Vercel. `maxDuration` is set on every route that can call a model, 60 seconds
on the packet, extract and check routes. `next.config.ts` traces `prompts/**`
and `seed/**` into the serverless bundle, since both are read from disk at
runtime and would otherwise vanish in production while working locally.

## How it is put together

```
prompts/*.md          System prompts. Never inlined in a route or component.
lib/ai/provider.ts    The only file that touches the model SDK.
lib/ai/prompts.ts     Loads prompts and fills {{TOKEN}} placeholders.
lib/verify.ts         Arithmetic, recomputed in process. Asks no model anything.
lib/misconception.ts  Three detectors in code, then a model judge on a shortlist.
lib/standards.ts      pgvector similarity search over $queryRaw.
lib/live/rules.ts     The interruption policy, as pure functions.
lib/limits.ts         Rate buckets and the spend ceiling, both in Postgres.
lib/copy.ts           Every user-facing string, and the em-dash ban.
lib/svg.ts            Sanitiser for model-written Method Match diagrams.
lib/exif.ts           Metadata stripping, in pure JS, before an image is sent.
seed/*.json           Hand-written. Not generated by a model.
scripts/check.ts      The deterministic test suite.
```

### Things worth knowing

**Arithmetic is never a model's job.** `lib/verify.ts` recomputes the answer
from the printed question using exact rational arithmetic, so `1/4 + 2/3` is
`11/12` and `0.1 + 0.2` is `3/10`, not `0.30000000000000004`. It reports three
states rather than two: agreement shows a **Checked** badge, disagreement shows
**Unverified** and the answer is stripped from the payload server side rather
than merely hidden by the component, and "no computable arithmetic" shows the
answer unbadged. That third state exists so word problems are not punished for
being unverifiable.

**The packet cache key deviates from the brief, deliberately.** The brief
specifies `standardCode:register:language`. That key is right for the reusable
half of a packet, the primer, the method comparison and the scripts, but it
would serve one problem's `lockedAnswer`, hint ladder and isomorphs for a
different problem on the same standard: a wrong answer shown to a parent behind
a "Checked" badge. So a hash of the normalised problem text is folded in as a
fourth component (`lib/packet.ts`). This keeps essentially all of the intended
saving, because the repeated case in practice is the same problem recurring
across worksheets rather than two different problems sharing a standard, and it
removes the possibility of showing an answer that belongs to a different
question. If you would rather have the literal key, it is one function.

**The em-dash ban is a guarantee, not a request.** It is in every prompt file,
and `sanitizeDeep` in `lib/copy.ts` runs over every parsed model response in
`lib/ai/provider.ts` before it reaches a component, so it holds even when the
model ignores the instruction.

**The answer appears in `lockedAnswer` and nowhere else.** Everything else in a
packet renders above the press-and-hold, so an answer mentioned in the primer or
in `whySchoolWay` defeats the lock. This is a rule in `generate-packet.md` and an
assertion in `npm run check` against the demo fixture.

**Nothing degrades to an error.** Rate limit, spend ceiling, model timeout,
malformed JSON, missing API key, missing database: every one of them serves the
cached demo packet with a banner that says accurately which of those happened.
The landing page "Try it" button runs entirely on the fixture, is never metered,
and carries all three registers, so the register control works on it with no
model call at all.

**Live Mode keeps nothing.** The rolling 30-second window lives in a ref in the
browser and is cleared when the session stops. The `Move` table has no
transcript column, so there is nowhere to write the words even by mistake. The
recap is written from move counts alone: the model that writes a parent's recap
has never seen a word their child said.

## Build status against the brief

Phases 1 to 6 are implemented. What is verified and what is not:

**Verified here** (`npm run check`, 91 assertions, plus a production build
served and inspected): arithmetic verification and its three states,
misconception detection, the Live Mode rule engine including the cooldown, the
three-card cap, the anxiety-band threshold and both Park It triggers, the
autonomy ratio, the em-dash ban, the SVG sanitiser, EXIF stripping, the cache
key, seed integrity, all ten routes returning 200, the register control
returning distinct copy for all three registers through the real API, and the
degraded path returning a usable packet rather than a 429 or an error page.

**Not verified here, and why:** this environment has no `OPENAI_API_KEY`, no
`DATABASE_URL` and no Vercel token, so the vision extraction, the generated
packet prose, pgvector retrieval, live classification and the deploy itself
have not been run against real services. The code paths exist and typecheck;
they have not been exercised end to end. The evaluation set below is the thing
to run once those three are in place.

### Evaluation set

Five inputs that must produce sane output before calling this done:

1. Fraction addition where the child added the denominators. Expect the
   misconception identified as whole-number bias. *The detector for this is
   covered deterministically in `npm run check`; the packet prose around it is
   not.*
2. Long division solved with the standard algorithm where the curriculum
   expects partial quotients. Expect Method Match to show both and mark both
   correct.
3. A word problem with no child work shown. Expect a hint ladder, and no
   misconception claimed. *`matchMisconception` returns null on empty working
   by construction.*
4. A deliberately blurry photo. Expect low confidence reported and the parent
   asked to retype, with no hallucinated transcription.
5. The string "I was never good at math either" in Live Mode. Expect an
   `ANXIETY_STATEMENT` card within five seconds. *The rule engine half is
   covered in `npm run check`; the classification half needs a key.*

## Out of scope for v1

No child-facing UI of any kind. No auth beyond an optional magic link. No
payments. No admin CRUD panel; `/ops` is the only operator surface. No dark
mode. No native apps. No teacher portal. No multi-caregiver accounts. Math
only, grades K to 8, English UI.
